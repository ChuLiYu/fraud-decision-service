# ADR-005: Portfolio MVP as one Python decision service

- Status: Accepted
- Date: 2026-11-12
- Decider: project owner
- Changes: timing of [ADR-004](ADR-004-course-first-priority.md) (phases after phase 1 waited for the course submission); defers [ADR-002](ADR-002-java-decision-python-inference.md) (Java decision service) without rejecting it

## Context

Phase 1 (training, evaluation, decision-level analysis) is complete. The owner's next goal is a minimum viable product that runs from the public GitHub repository and can be listed on a résumé, at the lowest cost that still runs end to end. The owner chose:

- **Delivery:** a reader clones the repository and runs one command; CI shows the checks passing. No hosted public endpoint (scope keeps cloud deployment out).
- **Stack:** the lowest-cost option that runs, rather than the Java plus Python split in ADR-002.

Two constraints shape the design:

- Trained models and Competition Data cannot be redistributed ([dataset card](../data/dataset-card.md), rules 7B), so a fresh clone has no real model.
- History features need past transactions per card or client key; the MVP has no online feature store (scope S-9).

## Decision

- Build one Python service (FastAPI) in a new `service/` component that depends on `ml/` (`fraud_ml`), so preprocessing is the same code as training. It returns `approve`, `review`, or `decline` with score, model version, and policy version, keeps a decision log with idempotency keys in SQLite, and routes any scoring failure or timeout to `review` ([ADR-003](ADR-003-failure-routes-to-review.md)).
- **Serving model:** a variant trained without history features (request-time fields only). Its metric gap to the full model is reported, not hidden.
- **Runs without the dataset:** `docker compose up` builds a *demo model* trained at image build time on synthetic rows generated by code. Responses mark it as the demo model. With the dataset downloaded locally, `make serve-model` trains the real serving model and the service loads it from a mounted directory.
- **Policy:** score thresholds fitted on validation (decision evaluation, base scenario, 2% review capacity), stored in a versioned file.
- **CI:** a GitHub Actions workflow runs lint and tests for `ml/` and `service/` and builds the image, on synthetic data only.

## Alternatives considered

- **Java decision service plus Python inference service (ADR-002).** Stronger signal for Java backend roles; rejected for now on cost (two services, JDK install, more slices). Remains the planned upgrade path; the API contract is kept language-neutral so the Java service can replace the decision layer later.
- **Hosted public demo.** Rejected: hosting cost, operations, and a public endpoint serving a model trained on Competition Data.
- **Commit the trained real model.** Rejected: dataset terms (rules 7B).

## Consequences

- A clone runs end to end in minutes with the demo model; the real model needs the owner's Kaggle download.
- The served model is weaker than the evaluated one until online features exist (scope S-9).
- Course presentation work (S-19) is not cancelled by this ADR; its timing is the owner's call.
